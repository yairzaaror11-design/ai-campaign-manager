# אפיון מסכי דשבורד

גרסה: 1.0 | 26.10.2026 | סטטוס: אפיון יעד לאישור ומימוש מדורג

## מסך הבית `/app`
Header: 'בוקר טוב, {firstName}' או 'שלום, {firstName}' לפי זמן מקומי אם זמין; subheader 'הנה מה שקורה בעסק שלך'; CTA 'יצירת קמפיין' ו'שיחה עם הקמפיינר'.
KPI: הוצאות, לידים, CPL, קמפיינים פעילים, חשיפות, אישורים ממתינים. לכל כרטיס: ערך, יחידה, שינוי מול תקופה קודמת רק אם בר-השוואה, tooltip על נוסחה, זמן סנכרון. אין להציג 0 כשמידע לא זמין.
גרף: הוצאות ולידים לפי יום; בחירת 7/30/90 ימים ותאריכים מותאמים; גרף עם legend ו-tooltip; מצב ללא נתונים.
פאנל המלצות: כרטיס עם ממצא, בסיס נתונים, רמת ביטחון והצעת פעולה; לחיצה פותחת פירוט ולא מבצעת שינוי.
טבלת קמפיינים: שם, פלטפורמה, סטטוס, הוצאות, תוצאות, CPL, עדכון אחרון; כניסה לפרטים.
פאנל אישורים: פעולה, יוזם, תאריך, סיכון, כפתורי צפייה/אישור/דחייה בהתאם להרשאה.
## קמפיינים `/app/campaigns`
רשימה עם חיפוש, סינון מצב/חשבון/טווח, מיון, עימוד; פעולות 'צפייה', 'הכן שינוי', 'צור חדש'. מסך פרטים עם ביצועים, קבוצות מודעות, מודעות, תקציב, היסטוריית שינויים ומצב סנכרון.
## פעילות `/app/activity`
ציר זמן audit עם פילטרים actor, action, result, date; אירועים נגישים לקריאה, ללא סודות.
## התראות
מרכז התראות עם unread/read, קישור לישות, סוג חומרה, timestamp; התראות על הרשאה שפגה, כשל סנכרון, בקשת אישור.
## כל מצבי המסך
Skeleton loading; no-business; no-ad-account; empty-period; API failure עם retry; partial sync; no permission; mobile narrow layout.
## דוגמת מבנה
Topbar > Welcome > CTA row > KPI grid > chart + recommendations > campaigns table + approvals.

## עקרונות מחייבים
- המוצר הוא הרחבה של Campaign Bachat הקיים, לא מערכת חלופית.
- יש לבצע תחילה inventory לקוד, סכמת הנתונים, הנתיבים, הבדיקות והאינטגרציות הקיימים. אין להניח שמרכיב מסוים כבר עובד ללא בדיקה.
- ממשק עברי מלא RTL; תמיכה עתידית ב-i18n, נגישות WCAG 2.2 AA ככל הניתן.
- כל נתון עסקי מבודד לפי tenant/business; אימות ואישור בצד שרת, לא רק בממשק.
- שום פרסום, שינוי תקציב, הפעלת קמפיין, שליחת הודעה חיצונית או פריסה לייצור ללא אישור מפורש ותקף.
- כל פעולת שינוי חיצונית דורשת idempotency key, audit log, ניהול retries ומצב ברור למשתמש.
- אין להשתמש בנתוני דמה כאילו הם נתונים אמיתיים. נתונים לדוגמה רק במצב demo מסומן.
- כל מסך כולל loading, empty, error, success, permission-denied ו-mobile states.
